# VulcanBench Frontier v5: status for the owner (2026-11-19)

Written when the owner asked to resume Frontier v5 so it can replace
VulcanBench Frontier v4 as the headline coding suite, with a real spread of
task shapes and languages and without another suite that mostly measures
reverse-engineering a binary. The plan and the decisions are in
[ROLLOUT.md](ROLLOUT.md). Nothing here changes a frozen plan, the release 1
lock or a decision.

## Counts first

- **6 of 20 target tasks admitted** toward a headline release (the proposed
  release 2 target in ROLLOUT.md section 2). All six are F5, one per
  language. The seventh release 1 task, ferrycore, is opaque-component
  shaped and is not counted toward the target (ROLLOUT.md R2).
- **Release 1 is 7 of 7 tasks, frozen** as `frontier-v5` 1.0.0 (PR #258,
  composition v4, [PLAN-v4.md](PLAN-v4.md)).
- **Confirmation: GPT-6 Astra 0 of 21** complete passes at medium (95%
  interval 0% to 16.1%, PR #292). Claude Opus 5.5 was not run (the owner
  stopped Claude spend, DECISIONS.md 2026-11-10).
- **14 more tasks are built in `tasks/frontier-v5/` but not admitted**: 11
  were solved at the gate or never gated, 2 are withdrawn F1 scaffolds
  (OpenAPV, libmbus), and nx-digraph is now a DailyWork pilot.

## Which tasks are reverse-engineering or opaque-binary shaped

- **ferrycore-crossing-opaque-parity** (release 1, private) is the Frontier
  v4 lineage: match a hidden reference engine by experiment. Version 0.1.0
  shipped a binary and was solved by disassembly; 0.2.0 hides the engine
  behind a query-only service, so it is black-box characterization rather
  than binary reading, but it is the shape the owner wants gone.
- **bothycore-booking-opaque-parity** (rejected, private) is the same shape.
- **The F2 candidates** (comrak, phonenumbers, jsts) are not binary tasks,
  but they are parity tasks: make a target match a readable reference. Every
  one collapsed into running or translating the reference.
- **The six F5 tasks are not.** Each is a set of real upstream defects in an
  open source project, graded by upstream and held-out tests. The other
  built candidates (nx-digraph, geos, ioverlay, tseslint, commons-lang,
  fmt, yyjson, luxon, petgraph, sympy, nx-group) are F5-like bug fixes too.

## What blocks a public leaderboard

1. **No discrimination.** Seven tasks, one reference at one effort, 0 of 21.
   One solve moves the score by 4.8 points; most models would tie at zero.
   No model has been run on release 1 above medium effort.
2. **One reference.** The lock names Opus 5.5, which was not run.
3. **No sweep path.** Release 1 runs only through
   `scripts/frontier-v5/run_gate.sh` (three fixed references, medium, Harbor).
   The `vulcanbench` harness does not load Harbor tasks; its
   `--agent-container` mode covers codex and claude-code only, and DailyWork
   decision D5 is extending it to every adapter.
4. **No publishing pipeline.** No aggregation, results template, cards,
   traces exporter or site pages for Frontier v5, and Harbor jobs do not
   write `tool-calls.jsonl` (owner rule of 2026-10-29).
5. **Open decisions.** (d) publishing channel is open. (f) is decided only
   for private material (DECISIONS.md 2026-10-31); the six F5 tasks' golds
   and held-out cases are public in this repo.
6. **Paused by decision.** DailyWork decision D9 (2026-11-18) pauses
   Frontier v5 and archives Frontier v4 at DailyWork's launch; resuming
   amends D9.
7. **Host.** The gate and confirmation evidence (`~/vulcanbench-gate`,
   `~/vulcanbench-confirm`) is on the Mac Studio, not this Mac. The gate
   archives are in `vulcanbench-data-backup`; whether the confirmation jobs
   are backed up there is unverified. Sweeping ferrycore needs the private
   repo on the sweep host, and its traces can never be published.
