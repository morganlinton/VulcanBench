## (b) Per-candidate notes: predicted naive fix and the guard it should break

**1. Boost.URL path normalization and compare (PR #1009).** Symptoms: `url_view(".") == url_view(".")` hangs; `compare("/a/b/..", "/a/")` returns -1 although both normalize to "/a/"; `compare(".//b", "/b")` returns 0 although they normalize differently; `hash("/.") != hash("/")` while compare says equal; `url("a/..//b").normalize()` then iterating `encoded_segments()` asserts; `url("a/b").set_encoded_authority("h").path()` returns "/a/". The obvious first patch for the compare family is to special-case the trailing "." or ".." inside the old `consume_last` lambda (emit a trailing "/" when the last segment is a dot segment) while leaving `normalized_size` and the "%2F" decoding alone. The maintainer states what that does: with the old decoding kept, the existing test `compare("../a/b", "..%2Fa/b")` flips from +1 to 0 (commit 359816ee7 message), and because the two lambdas each kept their own count of pending ".." they disagree on where separators go, so fixing one without the other changes the order of unequal pairs that `std::map` tests in `test/unit/url.cpp` already pin. A compare-only fix also breaks the pre-existing hash checks (lines 1151 to 1420 at 21719d3b0 assert `std::hash<url_view>` equality for every pair with `compare == 0`), which forces the structural change of deriving the hash from the same walker. For the decoded-size family the naive fix is to bump `decoded_path_size` in `set_encoded_authority` only; the debug-build `check_invariants()` assertion reached by `resolve(url_view("sc:%00#"), url_view("///"), dest)` and the new tests for `set_user_impl`, `set_password_impl` and `set_userinfo_impl` catch the three siblings that were missed. Verification notes for the author: the hang fix (5 lines) must be in place before the compare rewrite's pairwise tests can run, and the shield commit (5ec0b824d) and the normalize segment-count commit (fff625eb2) must land together or the shield test asserts in `increment()`.

**2. ada URLPattern canonicalization.** Symptoms: `URLPattern({search: "\\?x"})` matches "x"; `URLPattern({pathname: "/a\\?b"})` matches "/a"; `URLPattern({port: "0080"})` throws; `file://host/:x` matches `file://host/a/b`; `new URLPattern("file://host:0").port` is empty; `{-:e}?.example.com` loses its braces on round trip; `https://example.com{` compiles to hostname "*"; `/users/1` matches without a base. The obvious first patch for the search/hash symptom is to stop stripping the leading "?" in `canonicalize_search` and leave `url_pattern_init::process` alone. #1171 explains the trap: the init path passed `get_search()` with its delimiter straight into "process a base URL string", so the helper's strip had been cancelling it; removing only the helper strip makes every WPT base-URL inheritance case in `urlpatterntestdata.json` produce a search beginning with "?". For the pathname symptom the obvious patch is to percent-encode "?" and "#" by hand before running the full parser; the WPT cases that expect c0-control stripping and dot-segment resolution to behave as the path state override does (and, after #1313, backslash to slash conversion for special schemes while opaque paths stay untouched) break. For the port symptom the obvious patch is `std::stoi` on the port string, which drops the "0" port that #1215 keeps for file patterns and breaks the 5-digit cap check (#1168 "the five-digit cap also miscounts because it includes the zeros"). For the braces symptom the obvious patch is the one #1191 applied (drop the "prefix code point is not empty" term) which still compares only the first character and leaves #1329's `{/ab:id}?` case wrong, caught by `urlpattern-generate-test-data.json`.

**3. Boost.Charconv floff.** Symptoms: `to_chars(6.654853158546871e-310, scientific, 15)` prints e-309; precision 25 output is two digits short; `59547781175.354644775390625` with fixed precision 14 ends in 63 instead of 62; `.0099995` with precision 4 prints "0.0010". The obvious fix for the power-of-ten carry is to add another special case next to the existing `decimal_exponent_normalized == 0 || remaining_digits == 1` branch (which was itself an earlier narrow fix for "0.099 -> 0.10 in the precision = 2 instance", per the removed comment); the random comparison against `std::to_chars` in `test/to_chars_float_STL_comp.cpp` (1000 values times precisions 0 to 99 per format) and the new fixed-round-up spot checks fail for the next leading-zero depth. The obvious fix for the missing digits is to pad the output to the requested precision with zeros; the precision tests in #310 compare exact digit strings and the STL comparison fails. The obvious fix for the halfway case is to round halfway values up (matching old MSVC CRT behaviour); `to_chars_float_round_half_even.cpp` and the STL comparison fail. The subnormal fix is a one-character constant change that is hard to locate but has no plausible wrong local fix; it is in the cluster because #310's test depends on it. This candidate has the smallest gold (12 lines) and the weakest floor-8 story of the six; it is ranked third because the interaction is documented in the review thread and the guard suite is strong.

**4. fkYAML block scalars.** Symptoms: `foo: |\n  a\nbar: 1` loses the `bar` entry; `foo: |\n\nbar: 1` (empty block scalar before a mapping entry) misparses; `--- >\nline1` at column 0 is rejected; a header on its own line (`foo:\n  |\n  bar`) fails with a mapping value indicator error; folded scalars lose a line break after an empty line before a more-indented line; a trailing line of spaces without a newline drops its line break. The obvious first patch for the single-character line is to special-case lines of length one in `determine_block_scalar_content_range`; the actual cause is an off-by-one in the `find('\n', ...)` start position that also affects where multi-line scalars end, and the yaml-test-suite cases KK5P and M6YH plus the existing block scalar unit tests pin that. For the empty-scalar-before-mapping symptom the obvious patch is to relax the error "The first non-empty line in the block scalar is less indented" for empty scalars; #618 instead removes the check and ends the scalar at a non-empty line at or below the parent indentation, and adds a tab-indentation error that the relaxed check would let through (the new tests assert the tab case still raises). For the header-on-its-own-line symptom the obvious patch is to take base indentation from the previous line unconditionally; #633 says headers sharing a line with a key, `- ` or `? ` must keep the current behaviour and #589's document-root rule must survive, which the `Deserializer_DocumentLevelBlockScalar` test and the negative cases `foo: >` and `- |` pin. The explicit regression #609 -> #616 in the sibling key subset is the clearest floor-8 proof in this repo and can be added to the cluster if the author wants a fourth file (deserializer.hpp). Note the single_include mirror: upstream tests include the split headers, but a task should state which header the hidden tests compile against.

**5. CLI11 TOML config reader and writer.** Symptoms: an indented `  key='''` multiline value comes back as `''\nmultiline content`; `'''"C:\temp\file"'''` loses its quotes and decodes `\t`; `[section] # comment` becomes a flag named `[section]`; a one-line `'''comment'''` swallows the rest of the file; `to_config` writes a "+" group's options twice and the file no longer round-trips ("too many inputs for a flag"). The obvious first patch for the multiline quotes is to skip the quote-stripping pass for any value that contains a quote character; the hundreds of single-line quoted-value cases in `ConfigFileTest.cpp` break, which is why #1463 threads a multiline flag through value normalization instead. The obvious patch for the one-line multiline comment is to check whether the line ends with `'''`; the opener itself ends with `'''`, so a bare `'''` line is treated as closed, which the existing multiline comment tests catch (hence the length >= 6 guard). The obvious patch for the duplicate output is to skip every nameless subcommand in `to_config`; plain nameless option groups are rendered as their own sections by the formatter and by `to_config`, so the existing option-group output tests fail (#1363 spells out the same trap for `get_options`). The Join-policy off-by-two is a one-token change whose wrong local fix (changing the fallback to always write the array form) breaks the round-trip tests for ordinary delimited vectors.

**6. HowardHinnant/date from_stream and to_stream.** Symptoms: parsing "10:29:51 PM" with `%I:%M:%S %p %z` into sys_time gives the AM result on libstdc++; parsing "13 01" with `%H %I` sets failbit; `%D` prints `01/05/-1` for year -1; `%F` prints `0-50-01-05` for year -50. The obvious first patch for %p is the one the maintainer proposed in issue #893 (`tm.tm_isdst = -1` before `time_get::get`), which the reporter tested: still broken, because libstdc++'s `time_get` validates the designator without writing `tm_hour`. The next obvious patch is to hard-code "AM" and "PM" string matching, which breaks the locale-dependent parse tests when run with `COMPILE_WITH_C_LOCALE=OFF` in a non-English locale and diverges from the `time_put` output used elsewhere in the header (#923 formats the locale's designators with `time_put` and matches them with `scan_keyword`). For the %H/%I relation the obvious patch is to drop the consistency check; the existing mismatch tests in `parse.pass.cpp` (destination preserved on mismatch) fail, and #925 notes the noon and midnight handling must stay separate. For %F the obvious patch is `setw(5)` for negative years; the positive-year expectations in `format/range.pass.cpp` ("0050-01-05") fail, so the fix must use `std::ios::internal` like `operator<<(year)`. Verification caveat: #923's code is inside `#if !ONLY_C_LOCALE`, so the container must generate a UTF-8 locale and the task should run the test in both locale modes.

## (d) Gaps and uncertainties

- Nothing was built. Build and test-time figures are estimates from project size and dependency lists; Boost superproject builds for ranks 1 and 3 (and the Boost.JSON reserve) need the 1.92.0 tarball vendored into the image, and the exact 1.92.0 release date was not on boost.org (the site states releases ship in April, August and December; the Boost.URL commit messages say the error-category layout changed "Since 1.91", so 1.92 is the August 2026 release and does not contain PR #1009).
- Rank 1 gold is large because the maintainer rewrote two lambdas into a class; an author should check whether a 150 to 250 line minimal fix passes the new pairwise tests before fixing the task's gold size. The compare rewrite changed "253 pairs changed order" (commit message), so any std::map ordering test in downstream code is a risk for a model but not for upstream tests.
- Rank 2: the ada test binary pulls simdjson and GoogleTest through CPM at configure time; offline builds need `CPM_SOURCE_CACHE` or `CPM_USE_LOCAL_PACKAGES`. The URLPattern tests also need a regex provider; upstream CI uses std::regex for tests (`ADA_USE_UNSAFE_STD_REGEX_PROVIDER`). The ada fast path in #1167 is performance-sensitive (CodSpeed flagged #1329 as a 6.55% regression), so a correctness-only hidden suite will not catch perf regressions.
- Rank 3: the floor-8 story rests on the removed special case in #312 and on the randomized STL comparison test; the random test is seeded per run, so the author should confirm it fails deterministically against each naive patch, or pin a seed.
- Rank 4: fkYAML tests fetch doctest and the yaml-test-suite with FetchContent; both need vendoring. Every fix must be mirrored into `single_include/fkYAML/node.hpp` upstream; the task should decide which header the hidden tests compile against. The yaml-test-suite runner has an allow-list of known failures that moves with every PR; the task's guard should pin the state at the chosen base.
- Rank 5: CLI11's #1369 bundles non-config changes (Formatter, ExtrasError); the cluster uses only its three Config_inl.hpp items. Catch2 v2 is downloaded at configure time if not installed.
- Rank 6: #923 is locale dependent (`!ONLY_C_LOCALE` branch, libstdc++ `time_get` behaviour); the container needs a generated UTF-8 locale and the result may differ under libc++. The date test build compiles about 100 executables; limiting to `date_test` (not `tz_test`) keeps it under 10 minutes and avoids tzdata downloads.
- Contamination: all six clusters were merged after 2026-06-01, but five of the six repositories are widely used and the PR bodies, issue threads and commit messages describe the fixes in full. Models released after October 2026 may have seen them; the task should hide issue numbers and PR titles in prompts.
- Not surveyed in depth because of size or licence: ICU (too large per the brief), CGAL (GPL for most packages), Qt, LLVM, OpenCV, DuckDB, ClickHouse, Arrow, Protobuf, gRPC. Candidate-rich repositories left for a second pass if the six above fall through: boostorg/json parse_into, simdjson JSONPath, cpp-httplib SSE parser, manifold edge_op, Poco PR #5563, Boost.Decimal parsing.
