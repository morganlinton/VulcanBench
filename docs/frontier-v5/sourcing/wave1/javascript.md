# F5 wave 1 sourcing: JavaScript and TypeScript

Date: 2026-10-24. Sourcing only (no task building, no model runs, nothing executed locally).

Target: upstream fix clusters for F5 (concentrated multi-bug correctness) with floor 8 ("the obvious fix is wrong in a way the project's own tests detect") as the first filter and interaction between fixes as the second. Earlier sweeps over about 45 JavaScript projects found interaction-free clusters (marked, csv-stringify, cron-parser) and one qualifying cluster (typescript-eslint no-unnecessary-type-parameters) that fell in 12 minutes because nothing in its suite punished the obvious fix.

Method: `gh search prs --merged --merged-at ">=2026-06-01"` over 55 repositories (titles saved under the session scratchpad, `scratchpad/prs/*.json`), then `gh pr view`, `gh api .../pulls/N/files` and `gh pr diff` on every cluster that showed regression, revert, follow-up or "depends on" language. Gold sizes below are source lines only (tests, fixtures, changelogs and docs excluded) and come from the per-file additions and deletions GitHub reports. Expert hours are estimates for a strong JavaScript engineer who does not know the project, working from symptoms alone. Nothing was built or run, so feasibility statements are read from repository configuration, not measured.

Exclusions honoured: luxon, typescript-eslint, marked, csv-stringify, cron-parser; security-patch clusters (the zod and immer `__proto__` series, jsdiff #697, picomatch's ReDoS origin) were not used as causes.

## (b) Predicted naive fix and the guard it should break

Candidate 1, babel block-scoping. Symptom from #18191: `for (let i = 0, f = () => i; i < 1;) { i = 42; log(f()) }` logs 42 instead of 0. The obvious fix is to snapshot the binding where the closure is created, for example rewriting the head to `let _i = i, f = () => _i` at the declarator, or treating a head closure like a body closure (`capturedInClosure = true`) so the whole loop body gets wrapped in `_loop`. The first breaks `general/for-head-closure-mutated-in-head/exec.js` (`set = (i = 1)` later in the same head must be visible to `f`, so `log` must equal `[1]`; and `b = i++` after `g = () => i` must make `g()` return 1), which is precisely what the maintainer rejected in review on #18195. The second changes `output.js` in `general/for-head-closure-nested-not-mutated` (the inner loop must stay unwrapped and uncopied; only the enclosing loop is wrapped) and other fixtures whose output pins no `_loop`. For #18319, the obvious fix is to stop emitting the TDZ sentinel for head declarations at all; `tdz/for-head-closure-exec/exec.js` requires a `ReferenceError` for `for (let f = () => i, g = f(), i = 0;;)` and requires `shadowsOuter()` to return `"outer"`. For #18087, the obvious fix is to initialise every uninitialised head `let` with `void 0`; #18088's body says top-level heads are deliberately left alone, so existing `output.js` fixtures with `for (let x;;)` heads change (verify which ones when authoring; a shallow clone was not made for this note).

Candidate 2, prettier comments. Symptom from #19271: `(a = c /* comment */);` formats to `a = c /* comment */;` and then to `a = c; /* comment */`. The obvious fix is #19273: whenever a trailing comment sits before a closing parenthesis with no following node, attach it to the enclosing statement so the output is the fixpoint immediately. It was reverted within hours because a `prettier-ignore`d parenthesised node then loses its parenthesis and gains a semicolon, producing a SyntaxError on the second pass; the `tests/format/js/ignore/` fixtures and the second-pass idempotency check that the format test harness runs on every fixture catch it. The narrower obvious fix for the sequence case (attach the comment to the last sequence element in every parenthesised context) changes `for (;; a, b /* c */)` and `foo((a, b /* c */))` snapshots that #19263 explicitly left unchanged. The nested case (#19893) cannot be fixed inside the handler because only `enclosingNode` is available; the correct fix changes `attach.js` to expose the ancestor chain, and a local special case for `AssignmentExpression.right` leaves `x = y = (a = c /* c */)` and the arrow-chain fixture (`js/arrows/arrow-chain-with-trailing-comments.js`, graduated by #19930) unstable.

Candidate 3, zod optionality. Symptom from #6434: `z.object({ a: z.coerce.string().exactOptional() }).parse({})` returns `{ a: "undefined" }`. The obvious fix is either the "OPTION B PROTOTYPE" hunk inside `$ZodExactOptional`'s parse (return the payload untouched when the value is `undefined`), which #6438 reverted because it made `z.exactOptional(z.undefined())` reject `{ a: undefined }` and replaced specific error types with `nonoptional`, or a gate in `handlePropertyResult` that drops any absent key whose schema has `optin !== undefined`. The second breaks `optin-ladder.test.ts` "key-level admissibility across every rung" (`z.string().catch("C")` must fill `{ a: "C" }`, `z.transform(() => "T")` must fill `{ a: "T" }`, `.default("D")` must substitute). A fix applied only in `schemas.ts` passes the interpreted tests but fails the `jitless=false` variants and the compile-mode project, because the JIT fastpass and `compile.ts` emit their own `if (value !== undefined || key_present)` checks. For #6440 and #6462, the obvious fix inside `$ZodCatch` (copy the issues array before running the inner and compare lengths) leaves the pipe case broken: `catch.test.ts` requires `z.strictObject({a: z.string()}).pipe(z.any().catch("CAUGHT"))` to still fail with `unrecognized_keys`, which only holds when the inner runs on its own payload.

Candidate 4, immer array-methods. Symptom from #1255: after `d.reverse()` inside a recipe, `d[0].id = 99` mutates the base. The obvious fix is to draft any draftable, non-draft value the get trap returns while `allIndicesReassigned_` is set. That drafts values the user assigned themselves (`draft.push(newObj)`), which the suite asserts are returned as-is (`isDraft` false, patches `add` with the raw value) in every one of the nine configurations, and it changes behaviour in the plugin-disabled controls that #1289 and #1314 added. The merged fix instead records `baseRefs_` at the first reorder and drafts only members of that set; #1314 later removed the extra `assigned_` guard that #1255 had added, so an author who copies #1255's guard reproduces #1314's bug and fails its 131 lines of tests. For #1316, the obvious fix is to suppress nested patches whenever the parent array was reordered; existing patch tests for children modified at indices that exist in the base require those patches, and inverse patches must remain unchanged ("Inverse patches are fine").

Candidate 5, picomatch. Symptom from #99: `picomatch('**.thing.js')('somepath/test.thing.js')` is true. The obvious fix is to change the `**` handling in the main parser (`parse()`), where `**` adjacent to literals is already a single star; that changes regex sources asserted in `test/api.makeRe.js` and bash fixtures in `test/globstars.js` while leaving the real bug, which lives in `parse.fastpaths` where the `.ext` stripping reduces the base to a bare `**`. For #182, the obvious fix is to drop the 4.0.4 repeated-extglob rewrite, which fails `test/options.maxExtglobRecursion.js`; the correct fix keeps the rewrite and preserves every alternation branch. For #198, making the slash before a terminal `/**` always optional breaks the `strictSlashes` fixtures the PR says it preserves. For #196, un-gating `[!...]` without the first-position rule makes `[a!]` and `[\!a]` stop matching `!`, which `test/brackets.js` now pins.

Candidate 6, magic-string. Symptom from #282: content appended at the edge of a range disappears when the range is removed. The obvious fix is to stop clearing `intro` and `outro` in `remove` for every chunk in the range; the guard "should remove interior inserts" (expects `a;`) fails because inserts strictly inside the range must still go. The merged fix clears `intro` only when the chunk begins after `start` and `outro` only when it ends before `end`; even that leaves #358's case (an empty insert inside the removed range splits the chunk and `Chunk#split` drops the moved outro through `edit('', false)`), so a fix confined to `MagicString.remove` leaves `remove.test.ts` cases added by #358 and the `replaceAll('')` path failing. For #361, applying `contentOnly` to every chunk in the range makes plain `overwrite()` keep interior inserts, which the overwrite tests forbid.

## (d) Gaps and uncertainties

- Nothing was built or run. Suite runtimes, offline install behaviour and Node 22 compatibility are read from configuration files and PR bodies and must be verified by the authoring step. In particular: Babel's yarn global cache (no committed `.yarn/cache`), Prettier's full `tests/format` runtime, zod's `nub` wrapper and `.nvmrc` of 24, and the magic-string test-tree move between #349 and #358.
- Babel: the claim that initialising every head declaration changes existing `output.js` fixtures rests on #18088's body; the specific fixtures were not enumerated (no clone made). The 7.x backports (#18364, #18370) mean the same fixes exist on two branches; author from `main` (Babel 8).
- Prettier: comment attachment fixes change snapshots in `tests/format` directories beyond the ones each PR names; the authoring step needs the full post-fix snapshot set to avoid false negatives. Several of the "unstable" entries removed from `failed-format-tests.js` were previously skipped, so the pre-fix suite did not fail on them; guards come from the idempotency check and adjacent snapshots, not from those entries.
- Zod: the zod PR bodies (and some babel, immer, fast-check and prettier PRs) are AI-authored or AI-assisted and read as complete write-ups of the fix; the public record is a strong contamination vector for any model trained after September 2026, but all clusters postdate the June 2026 cutoff of the model under evaluation.
- Interaction strength varies: babel, prettier and zod have fixes that cannot be applied or do not compile without an earlier one; immer, picomatch and magic-string have same-function coupling and explicit "depends on" or "earlier fix incomplete" statements but each fix could be applied in isolation.
- Two clusters contain a fix that changed an existing test's expectation (magic-string #349 tightened "should remove interior inserts"; vue #15538 corrected "repeated expression in expressions"; picomatch #199 rewrote `api.scan.js` expectations). For those, the pre-fix suite enshrines the old behaviour, so the authoring base must drop or update those tests before guards are selected.
- graphql-js was placed in reserve on floor-8 strength alone; its feasibility (npm, node:test on source, no build, MIT) is the best of any repo surveyed, and the rule is hard enough for 4 to 8 expert hours. If the authoring step wants a second TypeScript candidate, start there.
- Search coverage: `gh search prs` caps at 300 results per query, which truncated prettier, vuejs/core, vitejs/vite and fast-check; the truncation affected June 2026 entries for those four. One rate-limit failure (decimal.js) was retried successfully.
