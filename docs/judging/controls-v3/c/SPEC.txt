Implement ledger.c (C11, libc only, one file that carries its own declarations, no header) with enum ledger_status parse_records(const char *text, struct record *out, size_t *count, int *error_line), enum ledger_status fee_cents(const char *kind, long long amount_cents, long long *fee), enum ledger_status balances(const struct record *records, size_t count, struct balance *out, size_t *out_count), and void render(const struct balance *totals, size_t count, char *buf, size_t buf_size), where LEDGER_MAX_RECORDS is 256, LEDGER_NAME_MAX is 32 (account and kind, including the terminator), struct record { char account[LEDGER_NAME_MAX]; char kind[LEDGER_NAME_MAX]; long long amount_cents; }, struct balance { char account[LEDGER_NAME_MAX]; long long cents; }, and enum ledger_status { LEDGER_OK = 0, LEDGER_E_FIELDS, LEDGER_E_KIND }. Input lines are date,account,kind,amount_cents; amount_cents is an integer. Blank lines and lines starting with # are skipped; any other line without exactly four fields returns LEDGER_E_FIELDS and stores the line number in *error_line. Fees: card is 2.9 percent of the amount, rounded half up to whole cents, plus 30 cents; bank is a flat 25 cents; cash is free; any other kind returns LEDGER_E_KIND. Balances are the per-account sum of amount minus fee. render writes 'ACCOUNT  BALANCE' lines separated by \n into buf, sorted by account, balance in dollars with two decimals, negatives in parentheses. Buffers are fixed: parse_records stores at most LEDGER_MAX_RECORDS records, and a line that does not fit the limits or whose amount is not an integer is reported like a field-count error; render never writes past buf_size and always terminates buf.
